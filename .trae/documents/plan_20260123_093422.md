# 优化代码架构：装饰器权限校验 + 分层重构

## 1. 创建权限装饰器模块 (app/decorators/permission\_decorators.py)

* 创建 `require_auth` 装饰器 - 验证用户已登录

* 创建 `require_superuser` 装饰器 - 验证用户是超级管理员

* 创建 `require_permission` 装饰器 - 自定义权限检查

## 2. 重构服务层 (app/service/user/user\_service.py)

* 移除所有 `HTTPException` 抛出

* 移除所有权限检查逻辑（移到 controller 层）

* 移除 `current_user` 参数（权限检查在 controller 层）

* 返回值改为：`dict` 或自定义结果对象（包含 success, data, error）

* 函数列表：
  - `create_user()` - 返回 dict
  - `get_user_by_id()` - 返回 Optional[User]
  - `list_users()` - 返回 List[User]
  - `update_user()` - 返回 dict
  - `delete_user()` - 返回 dict

## 3. 重构控制器层 (app/controller/api\_v1/user.py)

* 使用装饰器进行权限校验

* 在 controller 层处理服务层返回结果

* 在 controller 层抛出 HTTPException

* 将响应逻辑全部放在 controller 层

## 4. 创建通用响应模型 (app/models/response\_models.py)

* `SuccessResponse` - 成功响应

* `ErrorResponse` - 错误响应

## 5. 更新认证工具 (app/utils/auth\_utils.py)

* 添加 `get_current_user_optional()` - 可选的当前用户获取（用于不需要登录的接口）

## 核心改进

✅ 权限校验使用装饰器，代码更简洁
✅ 服务层纯业务逻辑，不处理 HTTP 相关
✅ 控制器层负责权限校验和响应处理
✅ 更清晰的分层架构
